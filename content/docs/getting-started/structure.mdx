# Project Structure

Ply uses a feature-based architecture to keep projects modular and easy to
navigate. This is the default structure generated by the CLI.

import { File, Folder, Files } from 'fumadocs-ui/components/files';

<Files>
  <Folder name="features" defaultOpen>
    <Folder name="[feature-name]" defaultOpen>
      <File name="handler.go" />
      <File name="service.go" />
      <File name="repository.go" />
      <File name="router.go" />
    </Folder>
  </Folder>

  <File name="main.go" />
  <File name=".env" />
  <File name="README.md" />
</Files>

## Structure highlights

- `features/`: application features. Each feature is self-contained.
- `features/[feature-name]/handler.go`: HTTP handlers.
- `features/[feature-name]/service.go`: business logic and domain rules.
- `features/[feature-name]/repository.go`: data access for databases,
  caches and external APIs.
- `features/[feature-name]/router.go`: route definitions and feature-level
  middleware.
- `main.go`: application entry point. It initializes the app and registers
  the feature routers.
- `.env`: environment variables such as `PORT`, `DB_URL` and secret keys.
- `README.md`: project documentation.

## Why feature-based

- **Modular.** Each feature is independent and easy to reason about.
- **Scalable.** New features can be added without touching unrelated code.
- **Maintainable.** Changes stay within the feature they belong to.
- **Testable.** Each layer within a feature can be tested on its own.

## Generated with the CLI

The structure is created by:

```bash
npx create-ply@latest my-app
```
